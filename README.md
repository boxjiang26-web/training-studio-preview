# 练记 · 训练工作台
个人教练与学员使用的本地试用版。教练管理档案、按日期编排草稿和发布，学员用手机浏览器打开当天训练，勾选各组并提交用力程度及备注。

## 试验入口
直接打开 http://127.0.0.1:4186/ 进入教练工作台。选择任一学员，点击「打开学员视图」即可体验当天训练和反馈。手机通过同一局域网的电脑 IPv4 地址和端口 4186 打开工作台；学员视图的链接也可直接打开。任何能访问试验地址的人都可以切换角色，请使用测试资料。

## 操作
1. 教练输入新学员姓名并建档。
2. 选择学员、训练日期，添加一个或多个动作，设置组数、次数或秒数并保存草稿，然后发布。
3. 打开对应的学员视图，可用日期与周历切换训练日。按实际情况勾组，选择 RPE 并提交训练备注。
4. 教练选择同一学员和日期，点击刷新记录即可核对各组状态、RPE、反馈编号与备注。
5. 草稿版本冲突时刷新后重新编辑。已提交反馈的训练日保留发布版本和反馈。数据库位于 data/，需一并保管。

## 启动和复验
本机使用 Node.js 24，依赖已装好。停止服务后，在此目录运行 powershell -ExecutionPolicy Bypass -File .\start.ps1，可在同一局域网访问。只在本机使用可运行 npm start（默认回环地址）。变更 app.tsx 后运行 npm run build。在已启动的实例运行 node verify.mjs，会通过 Chrome 新建两个合成测试档案，并将结果写入 acceptance.json。每次复验均使用独立的新档案。

## 实现
React + TypeScript 响应式页面，Node.js HTTP API，SQLite 持久化。此版本在一台电脑上运行一个服务进程，使用一个教练工作区。正式发布生成独立快照，场次反馈引用具体发布记录，每个发布记录至多一条反馈。学生身份来自服务端会话；读取或写入前检查记录归属。日期按设备当前本地日期默认选择。
## 动作资料库（2026-11-20）
教练可从页头「动作库」或日计划的「从动作库选择」搜索中英文名称、肌群和器械。打开卡片后可加入当日草稿，保存并发布后，学员可在对应训练日点击「查看动作示范」。直接入口为 http://127.0.0.1:4186/?library=1 。

catalog.json 保存了当日 ReadyNex 网页公开展示的 648 条动作元数据，来源为 app.readynex.cc 的公开目录构建 index-_lELHDmg.js 和入口 index-DQHFzp9i.js。613 条有官方 MP4 地址，35 条为无视频条目。完整视频与封面从官方媒体地址加载。GIF 模式在首次选择时截取视频开头最多五秒生成循环预览，后续复用 data/exercise-previews。生成器支持环境变量 FFMPEG_PATH，本机使用已安装的 FFmpeg。目录与已缓存 GIF 可在本机读取，完整视频、首次生成及封面依赖源站网络。node verify-library.mjs 可通过独立测试学员复验添加、发布和媒体播放。
## 两人协作与共享预览

开发环境使用 Node.js 24。两位开发者分别克隆同一个私有仓库，运行 npm ci、npm run build、npm start。每个人用自己的 GitHub 和 Codex 账号，在单独的功能分支提交，通过拉取请求合入 main。

catalog.json 是动作目录的共同来源。改动作后提交这个文件，部署时前端和服务端从同一版本构建。训练日、发布记录、学员反馈与 GIF 缓存保存在共享预览服务的 DATA_DIR。开发电脑各自的 SQLite 文件只用于本地测试。

仓库管理员在 Render Dashboard 新建 Blueprint，授权读取本仓库并选择 main。render.yaml 配置单个 Docker 服务、自动部署和 1 GB 持久化磁盘。Starter 实例与磁盘会收费，请在创建资源页面核对费用。初次部署使用空数据库。部署成功后把服务的 HTTPS 地址发给朋友，站点入口用户名为 studio，口令从 Render 的 PREVIEW_PASSWORD 环境变量读取并私下分享。进站后依然可以切换两种试验身份。

验收时先确认公网首页未认证返回 401、/healthz 返回 ok。两台设备登录同一站点，分别发布和读回一条测试计划。合并一次动作目录变更后，等 Render 显示对应提交上线，再刷新确认目录更新、原训练记录仍在。朋友需要自己的 GitHub 仓库写权限；向仓库 Settings → Collaborators 添加对方的 GitHub 用户名即可。
