# 练记 · 训练工作台
个人教练与学员使用的本地试用版。教练管理档案、按日期编排草稿和发布，学员用手机浏览器打开当天训练，勾选各组并提交用力程度及备注。

## 试验入口
直接打开 http://127.0.0.1:4186/ 进入教练工作台。选择任一学员，点击「打开学员视图」即可体验当天训练和反馈。手机通过同一局域网的电脑 IPv4 地址和端口 4186 打开工作台；学员视图的链接也可直接打开。任何能访问试验地址的人都可以切换角色，请使用测试资料。

## 操作
1. 教练输入新学员姓名并建档。
2. 选择学员、训练日期，添加一个或多个动作，设置组数、次数或秒数并保存草稿，然后发布。
3. 打开对应的学员视图，可用日期与周历切换训练日。按实际情况勾组，选择 RPE 并提交训练备注。
4. 教练选择同一学员和日期，点击刷新记录即可核对各组状态、RPE、反馈编号与备注。
5. 草稿版本冲突时刷新后重新编辑。已提交反馈的训练日保留发布版本和反馈。数据库位于 data/，需一并保管。

## 启动和复验
本机使用 Node.js 24，依赖已装好。停止服务后，在此目录运行 powershell -ExecutionPolicy Bypass -File .\start.ps1，可在同一局域网访问。只在本机使用可运行 npm start（默认回环地址）。变更 app.tsx 后运行 npm run build。在已启动的实例运行 node verify.mjs，会通过 Chrome 新建两个合成测试档案，并将结果写入 acceptance.json。每次复验均使用独立的新档案。

## 实现
React + TypeScript 响应式页面，Node.js HTTP API，SQLite 持久化。此版本在一台电脑上运行一个服务进程，使用一个教练工作区。正式发布生成独立快照，场次反馈引用具体发布记录，每个发布记录至多一条反馈。学生身份来自服务端会话；读取或写入前检查记录归属。日期按设备当前本地日期默认选择。
## 动作资料库（2026-11-20）
教练可从页头「动作库」或日计划的「从动作库选择」搜索中英文名称、肌群和器械。打开卡片后可加入当日草稿，保存并发布后，学员可在对应训练日点击「查看动作示范」。直接入口为 http://127.0.0.1:4186/?library=1 。

catalog.json 保存了当日 ReadyNex 网页公开展示的 648 条动作元数据，来源为 app.readynex.cc 的公开目录构建 index-_lELHDmg.js 和入口 index-DQHFzp9i.js。613 条有官方 MP4 地址，35 条为无视频条目。完整视频与封面从官方媒体地址加载。GIF 模式在首次选择时截取视频开头最多五秒生成循环预览，后续复用 data/exercise-previews。生成器支持环境变量 FFMPEG_PATH，本机使用已安装的 FFmpeg。目录与已缓存 GIF 可在本机读取，完整视频、首次生成及封面依赖源站网络。node verify-library.mjs 可通过独立测试学员复验添加、发布和媒体播放。
## 两人协作与共享预览

开发环境使用 Node.js 24。两位开发者分别克隆同一个私有仓库，运行 npm ci、npm run build、npm start。每个人用自己的 GitHub 和 Codex 账号，在单独的功能分支提交，通过拉取请求合入 main。

catalog.json 是动作目录的共同来源。改动作后提交这个文件，部署时前端和服务端从同一版本构建。训练日、发布记录、学员反馈与 GIF 缓存保存在共享预览服务的 DATA_DIR。开发电脑各自的 SQLite 文件只用于本地测试。

仓库管理员在 Render Dashboard 新建 Blueprint，授权读取本仓库并选择 main。render.yaml 配置免费 Docker Web 服务和免费 PostgreSQL。免费数据库适合试验，Render 当前限制是创建后 30 天到期。初次部署使用空数据库。部署成功后把服务的 HTTPS 地址发给朋友，站点入口用户名为 studio，口令从 Render 的 PREVIEW_PASSWORD 环境变量读取并私下分享。进站后依然可以切换两种试验身份。

验收时先确认公网首页未认证返回 401、/healthz 返回 ok。两台设备登录同一站点，分别发布和读回一条测试计划。合并一次动作目录变更后，等 Render 显示对应提交上线，再刷新确认目录更新、原训练记录仍在。朋友需要自己的 GitHub 仓库写权限；向仓库 Settings → Collaborators 添加对方的 GitHub 用户名即可。

## 团队工作台
在教练页建立团队并勾选成员。先在个人日计划保存所需动作，再从「团队工作台 → 模板与分发」保存模板，选择团队和日期即可分发。已有草稿或计划的成员会出现在跳过名单。周报按当前团队成员、周一到周日和每个学员每天最新发布版本统计。平均 RPE 只纳入已反馈场次，CSV 可查看逐场组数和学员备注。使用 node verify-teams.mjs 复验；STUDIO_URL 可指向独立测试实例。
## 测评 CSV 导入
打开教练页「学员档案 → 导入测评 CSV」，可下载模板。支持 UTF-8（含 BOM）和 GB18030 中文 CSV。必填列为学员姓名、测评日期、测评项目、成绩，单位可选。每批最多 300 条、128 KB。姓名唯一时自动匹配，重名或未命中时可按档案编号选择归属，也可忽略该行。确认时整批校验后入库。同一学员、日期、项目、单位下的相同成绩自动跳过，冲突值须先处理。学员档案「历次测评」按项目和单位分别显示成绩及相对上一次的数值变化。运行 node verify-assessments.mjs 可复验，STUDIO_URL 可指向独立实例。
## AI 辅助编排
在学员档案打开「AI 辅助编排」，选择学员与训练周，填写目标并生成草稿。服务端使用环境变量 DEEPSEEK_API_KEY 调用 DeepSeek；不要将密钥写入前端或版本库。模型参考目标周之前、最近八周内最多十场训练反馈及十六条测评记录。筛选截止于当前日期，历史不足时仍可生成。输入含自由文本，请在试验环境使用合成资料。

生成和保存修改仅写入教练草稿。可调整每天的动作、组数、次数或时长。确认时整周在一次事务内发布；已有个人草稿或发布记录的训练日会阻止整次发布，教练可移除 AI 草稿中该日动作后重试。空白日不发布。重复或过期版本不会覆盖新版本。SQLite 和 PostgreSQL 共用编排逻辑。使用 node verify-report.mjs 准备两名合成学员，再运行 node verify-ai.mjs 测试真实模型生成、逐日修改与发布。
## 学员训练记忆
教练页选择学员，进入「训练记忆 → 生成记忆建议」。程序在本机根据该学员最近六场反馈的 RPE 和完成组数、最近三条非空备注，以及同项目同单位最近两次测评的差值，生成带依据的候选。重复生成相同证据会保留原审核结果。可先修改措辞再接受，也可拒绝或撤回已接受记录。下一次生成 AI 周计划时只带上该学员当时已接受的记忆，草稿「参考记录」可查看当次快照。node verify-report.mjs 准备两名合成学员，node verify-memory.mjs 复验审核和实际模型调用。
## 教练与学员消息
教练在学员档案点击「学员消息」，学员在手机页点击「教练消息」。入口定期更新未读数，教练的学员下拉名单也显示对应学员的未读数。打开对话后标记已加载的对方消息为已读，更早记录可分页查看。消息为站内文字，单条限 2000 字。同一发送请求重试不会新增重复消息。免登录试验版允许主动切换角色，各学员会话仅能操作自己的对话。使用 node verify-messages.mjs 复验两名学员的收发、提醒和隔离。
## 多周训练周期
在学员档案打开「多周训练周期」，填写目标、开始周一与周期长度（2–52 周）。按周选择训练日，填写动作、组数和每组次数或秒数。保存周草稿后，可在下一周复用上一周保存的安排。百分比仅作用于每组次数或时长，四舍五入为整数（1–3600），组数和日程保留，也可继续手动修改。
确认发布按单周事务执行。遇到已有草稿或计划的训练日会整周回滚；已发布周锁定。学员手机页可从「已发布周期周」跳转对应周，也可用日历的上一周、下一周浏览。运行 node verify-cycles.mjs 可复验两个合成学员的复制、调整、发布、切周和归属隔离。
## 多周周期中的 AI 编排
从教练的学员档案进入「多周训练周期」，选择目标周期和要编排的周，点击「AI 生成本周草稿」。使用服务端 DeepSeek 配置，发送该周期的目标、周次、目标周之前七天该学员最新发布的日计划、完成组数、反馈和 RPE，以及已接受的训练记忆。未提交反馈的训练日保留为待反馈。生成结果保存为该周期的教练草稿，「本周编排依据」保留当次参考快照。逐日编辑后可保存或确认发布。运行 node verify-cycle-ai.mjs 可用两名独立合成学员和真实模型验证数据归属、修改和发布。
